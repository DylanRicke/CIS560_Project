# CS Pub Match Stat Tracker

A web app for tracking Counter-Strike pub match stats: browse and search matches, import a
match by hand, see a player's totals, best maps and monthly trend, and compare a player with
their friends.

- **Database:** SQL Server. Every statement the app runs is a stored procedure.
- **App:** ASP.NET Core 8 Razor Pages (C#). It reaches the database through plain ADO.NET
  (`SqlConnection`, `SqlCommand`, `SqlDataReader` from `Microsoft.Data.SqlClient`).
  No ORM is used. Column-to-object mapping is written by hand in `Data/Repositories.cs`.

## Running it

1. **Create the database** in SQL Server Management Studio or Azure Data Studio:
   ```sql
   CREATE DATABASE CSStats;
   ```
2. **Run the scripts in this order** against `CSStats`:
   `Database/Tables.sql`, then `Database/Procedures.sql`, then `Database/Data.sql`.
   All three can be re-run. Tables.sql drops and recreates the tables, and Data.sql clears
   the rows before inserting them.
3. **Set the connection string** in `App/CSStatTracker/appsettings.json`. The default points
   at Visual Studio's LocalDB:
   ```
   Server=(localdb)\MSSQLLocalDB;Database=CSStats;Trusted_Connection=True;TrustServerCertificate=True;
   ```
   For SQL Server Express use `Server=localhost\SQLEXPRESS;...`. For a server that uses a
   SQL login, replace `Trusted_Connection=True` with `User Id=...;Password=...`.
4. **Start the app.** Either open `CSStatTracker.csproj` in Visual Studio and press F5, or run:
   ```
   cd App/CSStatTracker
   dotnet run
   ```
   Then open http://localhost:5080. You need the .NET 8 SDK. The first build downloads the
   `Microsoft.Data.SqlClient` package from NuGet.

## Pages

| Players `/Players` | Search players by name, email or rank. | `Players_Search` |

| Compare friends `/Compare` | Compares a player with each friend over a date range. Add or remove friends. | `Report_FriendComparison`, `Friendships_ListForPlayer`, `Friendships_Add`, `Friendships_Remove` |

| Game modes `/Manage/Modes` | List, add and edit modes. | `GameModes_List`, `GameModes_Insert`, `GameModes_Update` |

## Aggregating queries

| Procedure | Parameters | Result columns | Shown on |
|---|---|---|---|
| `Report_PlayerTotals` | PlayerID, StartDate | PlayerID, DisplayName, GamesPlayed, TotalKills, TotalDeaths, TotalAssists, TotalDamage, TotalWins | Profile: totals tiles |
| `Report_FriendComparison` | PlayerID, StartDate, EndDate | FriendID, FriendName, FriendGamesPlayed, PlayerKD, FriendKD, KDDifference, PlayerADR, FriendADR, ADRDifference, PlayerWinRate, FriendWinRate, WinRateDifference | Compare friends |
| `Report_PlayerMapStats` | PlayerID, StartDate, EndDate | MapName, GamesPlayed, Wins, WinRate, AvgKills, AvgDamage, MapRank | Profile: best maps |
| `Report_PlayerMonthlyTrend` | PlayerID, StartDate, EndDate | Month, NumGames, KillDeathRatio, AverageDamagePerRound, WinRate | Profile: charts and table |

How the numbers are worked out:
- **K/D** = kills ÷ deaths. It's shown as "—" when there are no deaths.
- **ADR** = damage ÷ rounds played, where rounds played = `Team1Score + Team2Score`.
- **Win rate** is a percentage of games played. A tie counts as a game played but not a win.
- **Differences** are player minus friend, so a positive number means the player is better.
- **Friends:** Friendships stores each pair once, with the lower PlayerID first, so friends
  are looked up from both columns.
- **Map ranking** uses `RANK()` by win rate, with average damage breaking ties. Only maps
  with at least 5 games in the range count.
- **Removed matches:** matches with `IsRemoved = 1` are left out of every list and report.

## Constraints

- **Primary keys:** every table.
- **Unique:**
  - `Players.Username`, `Players.Email`, `Maps.MapName` and `GameModes.ModeName`
  - `PlayerMatchStats (MatchID, PlayerID)`: a player can be logged only once per match
  - `Friendships (PlayerID, FriendID)`
- **Foreign keys:**
  - Matches → Maps and Matches → GameModes
  - PlayerMatchStats → Matches and PlayerMatchStats → Players
  - Friendships → Players, twice (once for PlayerID, once for FriendID)
- **Check:**
  - Username length and email format
  - Rank, MapType and Result must come from fixed lists
  - Team size between 1 and 10, and max rounds between 1 and 60
  - At least one round played in every match
  - No negative stats, and headshots never more than kills
  - `Friendships.PlayerID < FriendID`, so each pair is stored once and nobody can friend
    themselves
- **In the procedures:** `Matches_Import` and `Matches_Update` also check the following and
  raise a readable error with `THROW` when a check fails:
  - Team size against the mode
  - Scores against the mode's round limit
  - Deaths can't exceed rounds played
  - No future dates

## Seed data

| Table | Rows |
|---|---|
| Maps | 14 |
| GameModes | 4 |
| Players | 150 |
| Friendships | 420 |
| Matches | 1,000 (6 soft-deleted) |
| PlayerMatchStats | 9,496 |

`generate_data.py` simulates every match round by round, so the numbers are consistent with
each other:
- Each team's kills equal the other team's deaths.
- Nobody dies more often than there were rounds.
- Every Result agrees with the score.
- Players only appear in matches after their join date.

The script uses a fixed random seed, so running `python generate_data.py` gives the same
`Data.sql` every time.

Player 1, **ManhattanMid**, is a demo account with 300 matches and 15 friends. They improve
over time, so their monthly K/D and ADR charts trend upward. That makes them the best account
to show in a demo.

## Schema notes

- `Matches.IsRemoved` (BIT, default 0) was added for soft deletes.
- The schema doesn't store which side a player was on. The import form groups players into
  Team 1 and Team 2 only to work out each player's Result. For the scoreboard, sides are
  worked back out from Result and the score. In a tied match everyone is shown in one group.
- For the same reason, editing a match can't change its score or player list. To change
  those, remove the match and import it again.
