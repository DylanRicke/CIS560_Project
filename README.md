# CS2 Stat Tracker — CIS 560 Team 7

A web app for tracking Counter-Strike 2 match stats: browse and search matches, import a match
by hand, see a player's totals, ranks, best maps and monthly trend, and compare a player with
their friends.

- **Database:** SQL Server, schema `Tracker`. Every statement the app runs is a stored procedure.
- **App:** ASP.NET Core 8 Razor Pages (C#). It reaches the database through plain ADO.NET
  (`SqlConnection`, `SqlCommand`, `SqlDataReader` from `Microsoft.Data.SqlClient`).
  No ORM is used. Column-to-object mapping is written by hand in `Data/Repositories.cs`.
- **Seed data:** generated by a C# console app (`tools/DataGenerator`).

## Running it

1. **Create the database** (or use the one the school gave the team):
   ```sql
   CREATE DATABASE CSStats;
   ```
2. **Run the scripts in this order** against that database:
   1. `Database/Tables.sql` (drops and recreates every table, so it also resets the data)
   2. `Database/Procedures.sql`
   3. `Database/Data/01_Players.sql` through `08_RankHistory.sql`, in number order

   From a terminal at the repo root, `sqlcmd` can run them all in one go:
   ```
   sqlcmd -S <server> -d CSStats -E -i Database\Tables.sql,Database\Procedures.sql,Database\Data\01_Players.sql,Database\Data\02_Maps.sql,Database\Data\03_GameModes.sql,Database\Data\04_Matches.sql,Database\Data\05_PlayerMatchStats.sql,Database\Data\06_Friendships.sql,Database\Data\07_Rounds.sql,Database\Data\08_RankHistory.sql
   ```
   (Use `-U <login> -P <password>` instead of `-E` for a SQL login.)
3. **Set the connection string** in `App/CSStatTracker/appsettings.json`. The default points
   at Visual Studio's LocalDB:
   ```
   Server=(localdb)\MSSQLLocalDB;Database=CSStats;Trusted_Connection=True;TrustServerCertificate=True;
   ```
   For the school server, change `Server` and `Database`, and replace `Trusted_Connection=True`
   with `User Id=...;Password=...`. Keep the password out of git: in Visual Studio right-click
   the project → *Manage User Secrets* and put the `ConnectionStrings:CSStats` value there.
4. **Start the app.** Open `App/CSStatTracker/CSStatTracker.csproj` in Visual Studio and press
   F5, or run `dotnet run` in `App/CSStatTracker`. Then open http://localhost:5080.
   You need the .NET 8 SDK.

## Regenerating the seed data

```
dotnet run --project tools/DataGenerator
```

This rewrites everything in `Database/Data/`. The seed is fixed (`Settings.Seed = 560`), so
everyone on the team gets identical data. Change the numbers at the top of
`tools/DataGenerator/Program.cs` (`Settings`) to get more or fewer players or matches. If the
team drops `Rounds` or `RankHistory` from the schema, set `IncludeRounds` /
`IncludeRankHistory` to `false` there too.

| Table | Rows |
|---|---|
| Players | 150 (a few soft-deleted) |
| Maps | 11 |
| GameModes | 4 |
| Matches | 1,200 |
| PlayerMatchStats | 13,682 |
| Friendships | 320 (Accepted, Pending and Declined) |
| Rounds | 22,248 |
| RankHistory | 6,604 |

The generator simulates every match round by round, so the numbers agree with each other:
- Scores follow the real CS2 formats: first to 13 for Premier and Competitive (Premier has
  overtime, Competitive can tie 12–12), first to 9 for Casual and Wingman.
- Every round row adds up to the final score, and each team's kills equal the other team's
  deaths.
- Every Result agrees with the score and the player's TeamNumber.
- Players queue in friend "stacks", so the friend comparison has real data.
- Premier rating moves after every Premier match, and Competitive rank moves per map.
- Before writing anything it checks its rows against the same rules as the CHECK, UNIQUE
  and FK constraints, and stops if any row would fail.

Players 1–4 (**Team7_Member1** … **Team7_Member4**) are demo accounts. They play a lot and queue
together, so they're the best accounts to show in a demo. Rename them in `Settings.DemoPlayers`.

## Pages

| Page | What it does | Procedures |
|---|---|---|

| Match details `/Matches/Details/{id}` | Scoreboard for each team with K/D, HS %, ADR and result, and the round-by-round timeline. Delete the match. | `Matches_Get`, `PlayerMatchStats_ListByMatch`, `Rounds_ListByMatch`, `Matches_Delete` |

| Players `/Players` | Search players by display name or SteamID. | `Players_Search` |

| Player profile `/Players/Profile/{id}` | Totals, three monthly trend charts with a table, Premier rating chart, Competitive rank per map, and a best-to-worst map table for a chosen date range. | Compare friends `/Compare` | Compares a player with each accepted friend over a date range. Send, accept, decline or cancel friend requests, and unfriend. | `Report_FriendComparison`, `Friendships_ListForPlayer`, `Friendships_Add`, `Friendships_Respond`, `Friendships_Remove` |
| Maps `/Manage/Maps` | List, add and rename maps. | `Maps_List`, `Maps_Insert`, `Maps_Update` |

## Aggregating queries

| Procedure | Parameters | Result columns | Shown on |
|---|---|---|---|
| `Report_PlayerTotals` | PlayerID, StartDate | PlayerID, DisplayName, GamesPlayed, TotalKills, TotalDeaths, TotalAssists, TotalDamage, TotalWins, AvgHeadshotPct | Profile: totals tiles |
| `Report_FriendComparison` | PlayerID, StartDate, EndDate | FriendID, FriendName, FriendGamesPlayed, PlayerKD, FriendKD, KDDifference, PlayerADR, FriendADR, ADRDifference, PlayerWinRate, FriendWinRate, WinRateDifference | Compare friends |
| `Report_PlayerMapStats` | PlayerID, StartDate, EndDate | MapName, GamesPlayed, Wins, WinRate, AvgKills, AvgDamage, MapRank | Profile: best maps |
| `Report_PlayerMonthlyTrend` | PlayerID, StartDate, EndDate | Month, NumGames, KillDeathRatio, AverageDamagePerRound, WinRate | Profile: charts and table |

How the numbers are worked out:
- **K/D** = kills ÷ deaths. It's shown as "—" when there are no deaths.
- **ADR** = damage ÷ rounds played, where rounds played = `Team1Score + Team2Score`.
- **Win rate** is a percentage of games played (`Result = 'W'`). A tie counts as a game played
  but not a win.
- **Differences** are player minus friend, so a positive number means the player is better.
- **Friends:** only `Status = 'Accepted'` rows count. The sender is in `PlayerID` and the
  receiver in `FriendID`, so friends are looked up from both columns.
- **Map ranking** uses `RANK()` by win rate, with average damage breaking ties. Only maps
  with at least 5 games in the range count.

## Design notes

- **Soft delete is on Players only**, because that's where the schema has `IsRemoved`. A removed
  player is hidden from lists, pickers and friend comparisons, but their past stat lines stay so
  scoreboards still add up. Matches have no `IsRemoved` column, so deleting a match is a hard
  delete of the match, its stat lines and its rounds, in one transaction. The page asks you to
  tick a confirm box first.
- **Team sizes:** `GameModes` only stores a name, so the import form's team size comes from
  `ModeRules` in `Data/Models.cs`: Premier and Competitive 5, Casual 10, Wingman 2, and 5 for
  anything else. The database itself allows up to 10 per team and scores up to 60.
- **Teams are stored** (`PlayerMatchStats.TeamNumber`), so the scoreboard always shows the right
  sides, including for ties.
- **Editing a match** can change the map, the date and each player's numbers, but not the score,
  teams or roster, because each Result and the match's Rounds rows depend on them. To change
  those, delete the match and import it again.
- **Imported matches** have no Rounds rows, because round-by-round data isn't entered by hand.
  Their details page says so.
- **Friend requests:** sending a request inserts a `Pending` row. If the other player had already
  sent one, sending back accepts it instead. A `Declined` request can be sent again.
- **Errors meant for the user** are raised with `THROW` (50001–50099), and constraint violations
  are turned into readable messages in `DbErrors` (`Data/Db.cs`).
